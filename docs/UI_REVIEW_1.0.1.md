# Bobola 1.0.1 UI, native, performance and security review

## Scope

This review covers the smallest practical improvement to the existing Svelte 5, Vite 7, Tauri 2, Rust and Windows WebView2 architecture. The narrow service rail remains available, the optional expanded sidebar remains the primary account list, and the floating dock remains available for compact navigation.

The visual reference was OmpDeck revision `071ef923e20529b9b59fb4a69d54ad499266b123`. The review used its centralized palette concepts, flat neutral surfaces, separators, compact density, explicit hover/active/focus states and system UI typography as reference points. OmpDeck code, runtime and fonts are not bundled.

## Changes

- Fixed service dock context-menu Manage, Reload and Close view callbacks. The service value is passed before the menu closes.
- Fixed the queued native dialog `close` event race that could dismiss a newly opened Manage dialog.
- Added regression coverage for dock context-menu Manage and the delayed dialog-close sequence.
- Kept the 48 px default rail and compact optional sidebar, with denser service rows so eight services fit the reference-sized window.
- Removed expensive dock backdrop blur and reduced shadow use. Dock and sidebar states now use subtle surfaces, hairlines, selected indicators, pressed states and visible keyboard focus.
- Applied the launch film's existing logo color treatment to the canonical Bobola assets and regenerated native icon sizes.
- Added the Bobola title to the Windows window configuration.
- Limited Vite release assets to the canonical app logos and pinned service artwork. Local design experiments are not emitted into `dist`.

## UI timing evidence

`scripts/ui-performance.mjs` ran an isolated Edge shell preview with eight saved services, three rounds of switching across all eight services, light and dark themes, two resize targets and 100%, 150% and 200% browser scale factors. It does not claim native WebView2 timing.

| Browser scale | Before ready ms | After ready ms | Before switch median / p95 ms | After switch median / p95 ms | After frame median / p95 ms |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100% | 351 | 433 | 33.3 / 263.0 | 33.3 / 281.6 | 16.7 / 16.9 |
| 150% | 191 | 241 | 33.4 / 33.9 | 33.3 / 33.5 | 16.7 / 16.8 |
| 200% | 199 | 279 | 33.3 / 33.5 | 33.3 / 33.7 | 16.7 / 16.8 |

The 100% p95 includes browser preview setup and persisted fixture transitions; the steady-state median is unchanged. Screenshots are in `output/ui-before` and `output/ui-after` during the local review and are regenerated by the script.

## Native resource evidence

The owned loopback benchmark ran on Windows 11 Enterprise, Intel i5-9400, six logical processors and 32 GiB RAM. It used eight local fixture pages, 48 static tiles per page, an ad-like request blocked by the native filter and a first-party pulse. The 10 second samples were process-tree measurements with shared PIDs deduplicated.

| Metric | Before | After |
| --- | ---: | ---: |
| Median private commit | 869.7 MiB | 870.2 MiB |
| Median summed working set | 1,547.9 MiB | 1,533.0 MiB |
| Median process count | 20 | 20 |
| CPU, one-core percent | 29.48% | 31.13% |
| CPU, whole-machine percent | 4.91% | 5.19% |
| Profile bytes after shutdown | 65.1 MiB | 64.1 MiB |

The before and after samples are one short run each and are close enough to be treated as equivalent within normal WebView2 startup variation. They do not substantiate an efficiency percentage against Ferdium. Existing longer comparisons remain documented separately in `docs/BENCHMARK_ANALYSIS.md`.

## Security and release review

- Shell commands require the `main` Tauri window label. Remote service views do not receive the Tauri command bridge.
- Native service storage uses separate profiles and the smoke test verifies cookie and local-storage separation after restart.
- The CSP blocks objects, frames and arbitrary remote connections from the shell; service URLs are hosted in separate native views.
- SVG artwork is pinned by source revision and SHA-256. Telegram's exact upstream bytes were restored after the baseline check found one missing whitespace byte.
- The source package scans included text for common private-key, GitHub token, AWS key and Slack token patterns, and for personal absolute paths. It excludes local data, build output, videos, orchestration notes and experimental files.
- Dependency notices are generated at `docs/DEPENDENCY_NOTICES.txt` and included with the installer. The installer is unsigned and WebView2 uses the download bootstrapper mode.

## Limits

The automated native checks use owned loopback fixtures and do not prove successful sign-in, notifications, calling, screen sharing, provider-specific popup flows or universal cosmetic-filter correctness. Those require manual checks with the relevant services and accounts. Inactive WebViews are unloaded only when the conservative lifecycle guards allow it; keep-live accounts, dirty pages, media and popup activity remain protected.
